# Agent identities: validation matrix and manual QA

Validation of the [agent identities ADR](../../adr/2026-11-17-agent-identities.md) against the ODP's test plan. Each
row says which automated tests cover it, and what is left for manual QA in the Testing column. Unit tests run with
`make test` (set `OBOT_TEST_POSTGRES_DSN` for the Postgres variants, as CI does). The integration tests in
[`agent_identities_test.go`](agent_identities_test.go) run with `make test-integration` against one in-process server
with authentication off, SQLite and Docker. `TestAgentVMCPConnection_NPXEverything`, like `TestMCPServerLifecycle_NPXEverything`, also needs MCP containers that can reach the npm registry. The e2e tests in
[`tests/e2e/llmgateway/agents_test.go`](../e2e/llmgateway/agents_test.go) run with `make test-e2e-llm-gateway` against two
real replicas on Postgres with authentication on.

## Manual QA checklist

Use a test deployment with two replicas on Postgres, authentication on, and a real OAuth provider (for example a
GitHub OAuth app). Use made-up agent names, and never paste real keys into the issue.

- [ ] **Q1. Same numeric ID.** Create agents until one has the ID of an existing user (for example 3). Give both access to the same shared vMCP and a model with a per-user budget. Connect both. Check that **Identity & Access > Agents > (agent)** and the user see separate connections, that budget usage and audit logs list them separately (the agent with an **Agent** badge), and that each one's key works only as itself.
- [ ] **Q8. Profile rename and delete.** Rename a profile with agent setup in the UI: its configuration and grants remain. Delete the profile: its configuration and grants are removed. In catalog YAML, rename a profile without an `id`: the old profile's setup is deleted (expected; the docs recommend an explicit `id`).
- [ ] **Q9. Legacy `*`.** Upgrade a deployment with a vMCP that has two **Everyone** profiles. Users still connect. An agent without an explicit profile gets 409 `agent_selection_ambiguous`, and the vMCP shows **More than one profile names every agent**.
- [ ] **Q10. Rollback.** Follow the rollback steps in the docs (**Agent identities > Roll back agent identities**), downgrade to the previous release, and check that it starts, users sign in, user API keys work, and the admin API key list loads. Upgrade again and check that agents' audit history is still there.
- [ ] **Q11. UI.** `?view=agents` and `/identity-access/agents/...` redirect to **API Keys**. The **Agents** tab appears with authentication on and off. On a catalog-synced vMCP, only **Agent setup** is editable. The **Everyone** option in model, skill, vMCP profile and guardrail filter editors says it includes agents. No configuration value or configured URL is ever shown.
